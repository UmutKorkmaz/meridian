# C — Optional integration packages design

Status: proposed. Inherits portfolio constraints and requires A's accepted baseline. Backend libraries remain outside the core dependency graph.

## Package boundaries

Meridian.Mediator.FluentValidation adapts existing FluentValidation validators into Meridian's Task<ValidationResult> contract. AddMeridianFluentValidation(IServiceCollection services, params Assembly[] assemblies) registers adapters once per request type, calls ValidateAsync and maps property/message errors. It works with regular and localized validation; it does not install MVC automatic validation.

Meridian.Mediator.Caching supplies memory and IDistributedCache providers implementing the existing untyped ICacheProvider. AddMeridianMemoryCaching and AddMeridianDistributedCaching registration methods accept options and register a single provider. Distributed serialization uses an explicit allowlisted JSON contract registry; it never resolves type names supplied by remote cache bytes. The serializer has GetContractId(Type type), Serialize(object? value, string contractId), and Deserialize(ReadOnlyMemory<byte> payload, string contractId). Each registered contract supplies a stable ID, schema version and JsonTypeInfo. Unknown or mismatched data is removed and treated as a cache miss with an observable diagnostic; transport/provider failure is propagated by default.

ApplicationKeyPrefix and an optional ICacheKeyScope.GetScope() decorate keys in the provider layer, consistently for get/set/remove. Defaults preserve current composed-key behavior. Tenant-scoped applications explicitly register an authenticated scope; tests prove tenant isolation. User-level responses require user-level scope or user-specific input keys; a tenant ID alone does not make private per-user data safe to share.

Optional miss coalescing uses a new optional core IConcurrentCacheProvider : ICacheProvider with Task<object?> GetOrCreateAsync(string key, Func<CancellationToken,Task<object?>> factory, TimeSpan? duration, CancellationToken cancellationToken). CachingBehaviorOptions.EnableRequestCoalescing defaults false. Coalescing is per provider instance and effective scoped key, not a distributed lock. A waiting caller's cancellation does not cancel the owner; owner cancellation faults the shared operation and a new request may retry. The provider never captures a scoped handler beyond its live owner request. Existing null-response cache policy remains unchanged.

Meridian.Mediator.Redis adds Redis leased idempotency, not an exactly-once external execution claim. Add ILeasedIdempotencyStore : IIdempotencyStore as an optional richer core contract. Task<LeasedIdempotencyClaim> ClaimAsync(string key, Type responseType, CancellationToken ct) returns LeasedIdempotencyClaim(LeasedIdempotencyStatus Status,object? CachedResponse,IdempotencyLease? Lease), with status values Claimed/InFlight/Completed/OutcomeUnknown. IdempotencyLease is a sealed record with string Key, string OwnerToken, string ResponseContractId and DateTimeOffset ExpiresAt. Task CompleteAsync(IdempotencyLease lease,object? response,CancellationToken ct), Task ReleaseAsync(IdempotencyLease lease,CancellationToken ct), and Task<bool> RenewAsync(IdempotencyLease lease,CancellationToken ct) validate ownership atomically; false renewal means ownership lost. Default LeaseDuration=30 seconds and CompletedRetention=24 hours are configurable adapter defaults, not new core defaults. The optional Redis package reuses Caching's allowlisted contract registry through an explicit package dependency.

Redis preserves pending/unknown records without automatic expiration by default, beyond lease expiration. An expired pending claim returns OutcomeUnknown and blocks automatic replay until application reconciliation; it does not become a fresh claim merely because a lease expires. Safe pre-side-effect failure may release a claim; generic handler cancellation/failure is conservatively unknown unless the application/provider proves rollback or no effects. Add optional Task ReconcileAsync(string key,string expectedOwnerToken,IdempotencyReconciliation resolution,object? response,CancellationToken ct) on the adapter, with resolution Completed or SafeToRetry. Reconciliation compares the stored owner token and known response contract. Administrative deletion/retention configuration explicitly ends replay protection and is not automated here. Completed null values are replayable using the known response contract; completed retention also bounds the replay guarantee. Owner tokens and schema/version checks prevent stale completion or release. Lua single-key transitions are used for broad Redis compatibility; failover guarantees and external side-effect uncertainty are explicitly documented. The existing atomic and non-atomic contracts retain their prior behavior.

Redis keys apply the configured ApplicationKeyPrefix and optional authenticated ICacheKeyScope consistently, including legacy methods and reconciliation. IdempotencyLease.Key is the effective owned key and is not decorated twice on completion/release/renewal. Different tenants/users cannot replay one another's results. A known key with an incompatible requested response contract fails clearly rather than deserializing into an unregistered type; no raw key/token/payload is included in default telemetry.

Meridian.Mediator.EntityFrameworkCore adapts scoped DbContext transactions. AddMeridianEfCoreTransactions<TContext>(services, Action<EfTransactionOptions>? configure=null) registers a scoped provider. Add optional ITransactionExecutionProvider.ExecuteAsync<T>(Func<CancellationToken,Task<T>> action, CancellationToken ct) so explicit execution-strategy composition can own the whole delegate. UseExecutionStrategy defaults false. Existing transactions are joined with a savepoint when supported; the adapter never commits/disposes a transaction it does not own. Without savepoints, joining requires explicit JoinWithoutSavepoint=true. Both original and cleanup errors remain observable. Automatic replay of a handler with arbitrary external side effects is not enabled by default.

Meridian.Mediator.AspNetCore contains exception/validation integration; samples/Meridian.AspNetCore is a net10 Minimal API example with a SQLite store. Validation maps to 400, missing identity to 401, authorization denial to 403, in-flight idempotency to 409, unknown outcome to a documented 409 response requiring reconciliation, and unexpected errors to redacted 500 ProblemDetails. Endpoint metadata carries correlation ID and public error codes, not payload/stack detail. Authentication and authorization happen before shared-cache lookup; tenant/user scope is required for personalized caches. OpenAPI describes real status codes and streamed responses.

## Compatibility and dependencies

FV and caching adapters target net8/net9/net10. The first EF adapter line uses EF Core 8 and targets net8/net9/net10; a separate isolated compatibility test lane checks EF Core 10. Raising a mandatory EF dependency major is a reviewed package-major change. ASP.NET integration targets the supported framework assets; the example remains net10. Core packages do not acquire backend dependencies or a service-locator global.

## Acceptance and tasks

C1 validation; C2 memory/cache contracts and optional coalescing; C3 distributed serialization/scope; C4 Redis ownership and uncertainty; C5 EF transactions; C6 HTTP integration. Each includes repeated-registration/scoped-lifetime tests, actual package consumption, documentation and E2 manifest entries. Real isolated Redis/relational tests cannot be replaced with mocks when claiming backend guarantees.
